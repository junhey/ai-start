RAG · Retrieval-Augmented Generation

为什么需要 RAG：四大痛点 — 知识截断 / 私有数据 / 可溯源 / 可更新。微调改不了知识，RAG 才能。

为什么需要 RAG

  • 知识截断：模型不知道训练之后的事
  • 私有数据：模型没见过你公司的文档
  • 可溯源：答案要能引用原文
  • 可更新：今天加文档，今天就能问
  • → 比微调便宜 10-100 倍

Embedding 直觉：一句话变成 1536 维向量。'猫'和'喵星人'近，'猫'和'汽车'远。

Embedding 是什么

  • 文本 → 一个高维向量（768 / 1536 / 3072 维）
  • 语义相近 → 向量相近
  • "猫" 和 "喵星人" 离得很近
  • "猫" 和 "汽车" 离得很远
  • 模型：OpenAI text-embedding-3 / BGE / GTE
三种相似度：余弦最常用。归一化后三者等价。一般直接用余弦就够了。

三种相似度

  • 余弦相似度 · cos(θ) ∈ [-1, 1] · 最常用
  • 点积 · 速度快，需归一化
  • 欧氏距离 · 几何直觉
  • 归一化向量后，三者等价
向量库选型决策：小项目 Chroma/pgvector，规模上来才换 Milvus/Qdrant。Pinecone 是 SaaS 不用运维。

向量数据库

  • Chroma · 轻量，本地起手
  • Milvus / Zilliz · 大规模生产
  • Pinecone · SaaS 标杆
  • Qdrant · Rust 实现，性能好
  • pgvector · Postgres 直接加
  • 小项目用 Chroma / pgvector，规模上来再换

Chunking 是 RAG 效果的第一胜负手。

切块策略：固定窗口 + overlap 是基线；按结构（Markdown 标题、章节）效果更好；按语义需要 LLM 协助；父子分块是 LangChain 推的高级用法。

Chunking 策略

  • 固定窗口 · 500 token 一段，简单粗暴
  • 滑动窗口 · 加 overlap，避免切断语义
  • 按结构 · 章节 / 段落 / Markdown 标题
  • 按语义 · LLM 协助找断点
  • 父子分块 · 子用于检索，父用于上下文
Hybrid Search：BM25 + 向量。术语/实体名/错别字 BM25 强，语义/同义改写向量强。RRF 融合是简单又好的方法。

Hybrid Search · 混合检索

  • BM25（关键词）+ 向量（语义）
  • 关键词擅长术语 / 实体名 / 错别字
  • 向量擅长语义 / 同义改写
  • RRF 融合排序，鱼和熊掌
Re-rank 是被严重低估的环节。召回 50 + 精排 5 比单纯召回 5 效果好得多。BGE-Reranker 开源够用。

Re-rank · 重排

  • 向量检索 top-50 召回，不一定是最相关的 top-5
  • 用 Cross-Encoder 二次精排
  • 代表模型：BGE-Reranker / Cohere Rerank
  • 代价：慢一些，但召回质量提升明显
长上下文压缩：召回 10 段太长怎么办？摘要 / 抽取 / LLMLingua 三种思路。

长上下文压缩

  • 问题：召回了 10 段，可能太长
  • 方案 1：摘要后再喂
  • 方案 2：LLM 抽取相关句子
  • 方案 3：LLMLingua 等压缩工具
评估必做：检索侧看 Recall@k，生成侧看忠实度。RAGAS 框架自动化。'没有评估，调优就是玄学'。

RAG 评估

  • 检索侧：召回率 / Recall@k / NDCG
  • 生成侧：答案准确率 / 忠实度 / 引用正确
  • RAGAS：自动化评估框架
  • 没有评估，调优就是玄学
进阶：GraphRAG 加图谱、Self-RAG 让模型自决、Agentic RAG 多轮检索、HyDE 让 LLM 先编个答案再检索。下一课 Agent 把这些技术串起来。

进阶变体

  • GraphRAG · 知识图谱 + 检索
  • Self-RAG · 让模型自己决定要不要检索
  • Agentic RAG · 多轮检索 + 推理
  • HyDE · 让 LLM 先编个答案再用它去检索
