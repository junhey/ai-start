模型能力 · 四件套

  • 理解 · 看懂输入：文本 / 图像 / 代码 / 数据

  • 推理 · 多步思考：规划、因果、反思
  • 调用工具 · 走出沙盒：函数 / API / Shell / RAG

金句：原始马力大 ≠ 能拉车。一辆车没有缰绳、没有刹车，越快越危险。这就是 AI 系统不带 Harness 的样子。

套在模型外面的工程系统：约束 + 验证 + 追溯 + 回退 + 沉淀 + 审批。

Harness = 套在模型外面的工程系统。六要素：约束 / 验证 / 追溯 / 回退 / 沉淀 / 审批。

Harness 全景图 (点击节点高亮)

全景图必讲：输入先过约束（护栏） → 模型干活 → 验证再放行；旁路有审批门、追溯日志、回退路径、沉淀环路。

① 约束 · Constraint

  • 边界：能做什么 / 不能做什么（白/黑名单）
  • 预算：步数 / token / 时间 / 金额上限
  • 资源：哪些工具能调、哪些目录能写
  • 输入护栏：长度截断、敏感词过滤、注入防御
  • 输出护栏：JSON Schema、内容审核、PII 脱敏
  • → 越自由的模型，越需要明确的边界
约束 ① 五件事：边界（白/黑名单）、预算（步数/token/钱）、资源（哪些工具能调）、输入护栏（长度/敏感词/注入）、输出护栏（Schema/审核/PII 脱敏）。强调'越自由的模型越需要边界'。

② 验证 · Verification

  • 语法验证：JSON / SQL / 代码可解析
  • 规则验证：必填字段、值域、引用完整性
  • 事实验证：引用是否在 RAG 检索结果里
  • 测试验证：跑单测 / 仿真 / dry-run
  • 双 LLM 互检：Critic 角色复核
  • "信任但验证" — 验证失败 = 重试或回退
验证 ②：语法、规则、事实、测试、双 LLM 互检。'信任但验证'。验证失败 = 重试或回退，不是当成对的吞下去。

③ 追溯 · Traceability

  • 请求级：trace_id 串起每一次调用
  • 步骤级：每个 thought / action / observation 都存
  • 引用级：答案的每一句来自哪段证据
  • 版本级：模型版本 + Prompt 版本 + 工具版本
  • 工具：LangSmith / Langfuse / Phoenix / 自建
  • → 能"复盘"的系统，才能"改进"
追溯 ③：trace_id 串起每一次调用，每一步思考、引用、版本号都要存。Langfuse / LangSmith 是主流工具。能复盘的系统才能改进。

④ 回退 · Fallback

  • 重试策略：指数退避、max retries、温度抖动
  • 降级方案：旗舰模型→中模型→规则脚本
  • 断路器：连续失败 N 次熔断，避免雪崩
  • 事务回滚：写库 / 发邮件等副作用必须可撤销
  • 人工兜底：模型放弃时切到客服
  • 回退 = 别让一次失败，毁掉整条流程
回退 ④：重试 + 退避 + 降级 + 断路器 + 事务回滚 + 人工兜底。'别让一次失败毁掉整条流程'。

⑤ 沉淀 · Distillation

  • 从日志学：失败模式归类、典型错误打标
  • 更新 Prompt：把教训写进 SYSTEM
  • 沉淀到规则：高频场景固化为代码
  • 构建评测集：把 bug 变成回归用例
  • 反哺微调：积累足够数据后做 SFT/DPO
  • → 系统越用越聪明，而不是越用越混乱
沉淀 ⑤：失败模式归类、Prompt 迭代、规则化、回归集、SFT 反哺。系统越用越聪明，而不是越乱。

⑥ 审批 · Approval

  • 风险分级：只读 / 可逆写 / 不可逆写 / 高风险
  • HITL · Human in the Loop：高风险操作必须人确认
  • 审批链：金额阶梯 → 不同审批人
  • 预览 + diff：让人看清"将要改什么"
  • 审计留痕：谁在何时批准了什么
  • 越自动化的系统，越需要"刹车手"
审批 ⑥：风险分级 + HITL（Human in the Loop）+ 审批链 + 预览 diff + 审计留痕。'越自动化越需要刹车手'。

没 Harness vs 有 Harness

裸调模型

  • Demo 5 分钟搞定
  • 线上 5 天就翻车
  • 错了不知道为什么
  • 改不动也回不去
→

带 Harness

  • 初期慢一点
  • 越跑越稳
  • 错了能定位
  • 能改也能回
对比页：裸调模型 demo 5 分钟搞定，5 天翻车；带 Harness 初期慢一点，但越跑越稳。这是开发者要做的工程价值判断。
