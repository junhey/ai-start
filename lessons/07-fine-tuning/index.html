全参 vs LoRA 的本质：要不要更新所有权重。70B 全参微调需要 1TB+ 显存，普通团队做不起。

全参 vs LoRA

全参微调

  • 更新所有权重
  • 显存爆炸（70B 需 1TB+）
  • 效果上限高
  • 代价昂贵
VS

  • 只训练低秩矩阵
  • 参数量减少 10000×
  • 消费级显卡可跑
  • 效果接近全参
LoRA 核心想法：大模型权重的'调整量'是低秩的，所以训一个小矩阵就行。

LoRA
核心
想法

大模型权重的"调整量"是低秩的。

讲一遍数学：原始 d×d 拆成 d×r 和 r×d 两个小矩阵，r=8 就能减 250 倍参数。

lora math


原始权重: W ∈ R^(d × d)            (d=4096, 参数 ≈ 16M)

LoRA 改造:
  W' = W + ΔW
  ΔW = B · A         B ∈ R^(d × r), A ∈ R^(r × d)
  通常 r = 8 / 16 / 64

→ 训练参数:  d × r + r × d = 2 d r
→ 当 r = 8:  16M → 65K, 减少 250 倍
QLoRA 把存储压到 4-bit，加上 LoRA，单张 24GB 显卡能微调 33B 模型。这是 2023 年最大的工程突破之一。

QLoRA · 4-bit 量化 + LoRA

  • 原模型权重压到 4-bit 存储
  • 前向时反量化，反向只更新 LoRA 部分
  • 单张 24GB 显卡微调 33B 模型
  • 效果几乎无损
PEFT 全家桶：LoRA 是工业主流，其他用得少但也要知道名字。

PEFT 全家桶

  • LoRA / QLoRA：业界主流
  • Prefix Tuning：在前缀加可学向量
  • P-Tuning：可学的"软"提示词
  • Adapter：在层间插入小模块
  • 没有银弹，按场景选
指令微调数据：1k 条精标 > 10w 条粗标。LIMA 论文证明了'Less is More'。

指令微调数据格式

  • 三段式：instruction / input / output
  • 对话式：messages: [system, user, assistant]
  • 规模：1k 条精标 > 10w 条粗标
  • 多样性：覆盖各类任务和长度
  • "Less is More" — LIMA 论文核心结论
DPO 取代 RLHF 是大趋势。数据格式 (prompt, chosen, rejected) 三元组，训练简单稳定。

DPO · 直接偏好优化

  • RLHF 复杂：要训奖励模型 + PPO
  • DPO 直接用偏好对训练，简单稳定
  • 数据：(prompt, chosen, rejected)
  • 已成为主流偏好对齐方法
  • 变体：IPO / KTO / ORPO
